Dart가 다른 언어와 무엇이 다른지, 그리고 Google이 Flutter의 언어로 왜 Dart를 선택했는지 다루는 강의다.
dart.dev는 Dart를 다음 세 가지로 소개한다.

- **UI에 최적화**되어 있다.
- **생산적인 개발 환경**을 제공한다.
- **모든 플랫폼에서 빠르다.**

## 1. 두 종류의 컴파일러: Dart Web / Dart Native

- **Dart Web**: Dart 코드를 **JavaScript로 번역**하는 컴파일러다.
- **Dart Native**: Dart 코드를 여러 CPU 아키텍처(ARM32, ARM64, x86_64)의 **기계어로 컴파일**한다.
  - Dart 하나로 iOS, Android, Windows, Linux, macOS를 모두 대상으로 컴파일할 수 있다.
  - 저사양 아키텍처로도 컴파일할 수 있어서 IoT 기기나 자동차에서 Flutter가 쓰이기도 한다.

## 2. JIT와 AOT를 모두 지원한다

Dart의 가장 큰 특징이다. 개발용 툴체인과 배포용 툴체인이 나뉘어 있다.

|       | JIT (Just-In-Time)                         | AOT (Ahead-Of-Time)         |
| ----- | ------------------------------------------ | --------------------------- |
| 사용 시점 | 개발 중 (Development toolchain)               | 배포 시 (Production toolchain) |
| 동작 방식 | **Dart VM** 위에서 코드를 실행                     | 네이티브 기계어(ARM, x64)로 미리 컴파일  |
| 장점    | 변경 사항이 즉시 화면에 반영됨 (hot reload, 풍부한 디버깅 지원) | 실행이 빠르고 시작 시간이 짧음           |
| 단점    | VM 위에서 돌기 때문에 느림                           | 최적화 과정 때문에 컴파일이 오래 걸림       |

### AOT만 있는 언어의 문제

C, C++, Rust, Go 같은 언어는 개발을 마친 뒤 대상 아키텍처(예: Windows)용 바이너리로 컴파일하고, 그 바이너리를 배포한다.
이 컴파일은 여러 최적화를 수행하기 때문에 시간이 오래 걸린다.

UI를 만들 때는 이 방식이 맞지 않는다. 버튼 하나, 메뉴 하나를 고칠 때마다 전체 프로젝트를 다시 컴파일해야 결과를 볼 수 있다면 개발 경험이 매우 나빠진다.
**개발 중에는 빠르게 반복(iterate)하고 결과를 바로 확인할 수 있어야 한다.**

### Dart의 해결 방식

- **개발 중**: JIT 컴파일러가 Dart VM 위에서 코드를 실행한다. 코드 실행 자체는 느리지만, 변경 결과를 몇 초~몇 밀리초 안에 화면에서 확인할 수 있다.
- **배포 시**: AOT 컴파일러로 네이티브 기계어를 만든다. 사용자의 기기는 VM 없이 컴파일된 기계어를 실행하므로 앱이 빠르다.

모바일 개발에는 **개발할 때 빠른 피드백**과 **배포했을 때 빠른 앱**이 둘 다 필요하다. 두 방식을 모두 제공하는 언어는 많지 않다는 점이 Dart의 차별점이다.

## 3. Null Safety

- Java, C++처럼 null safety가 없는 언어에서는 개발자가 null 값을 참조해 프로그램이 크래시 나는 문제가 흔하다.
- Dart는 **sound null safety**를 도입했다. 값은 개발자가 허용하지 않는 한 null이 될 수 없어서 더 안전한 프로그램을 만들 수 있다.

## 4. Flutter가 Dart를 선택한 이유

1. **JIT와 AOT를 모두 지원한다.** 모바일 앱에는 개발 중 빠른 피드백과 빠르게 동작하는 최종 앱이 모두 필요하다.
2. **Dart와 Flutter 모두 Google이 만든다.** Flutter에 필요한 기능이 있으면 **언어 자체를 수정**할 수 있다.
   - React(Facebook)는 JavaScript를, Django는 Python을 바꿀 수 없다. 언어의 규칙 안에서만 최적화해야 한다.
   - Flutter FAQ에 따르면, Flutter가 Dart를 채택했을 당시 Dart에는 네이티브 바이너리를 만드는 AOT 툴체인이 **없었다**. 지금의 AOT 툴체인은 Dart 팀이 Flutter를 위해 만든 것이다.
   - Dart VM도 원래는 처리량(throughput) 위주로 최적화돼 있었지만, 지금은 Flutter에 더 중요한 **지연 시간(latency)** 쪽으로 최적화하고 있다.

## 정리

- **JIT** 덕분에 코드 변경 결과를 즉시 확인할 수 있어 개발 경험이 좋다.
- **AOT** 덕분에 여러 CPU 아키텍처용 빠른 네이티브 바이너리를 만들 수 있다.
- **Flutter 팀과 Dart 팀이 긴밀히 협력**하므로, 프레임워크에 필요하면 언어가 그에 맞게 최적화된다.
