Dart의 **Null Safety**가 무엇이고, nullable 변수를 어떻게 선언하고 안전하게 사용하는지 다루는 강의다. [[1. Why Dart]]에서 예고했던 내용이다.

## 1. Null Safety란

Null Safety는 **개발자가 null 값을 참조하지 않도록 도와주는 기능**이다. Dart에 처음부터 있던 기능은 아니고, 이후 버전에서 추가됐다.

- null 값을 참조하면 **런타임 에러**가 난다. 즉 사용자가 폰에서 앱을 쓰는 중에 에러가 발생한다.
- 이런 에러는 **컴파일하기 전에 잡는 것**이 이상적이고, 그 역할을 하는 것이 Null Safety다.

## 2. Null Safety가 없으면 생기는 문제

강의에서는 dart.dev의 「Understanding null safety」 문서 예제로 설명한다.

```dart
// Without null safety:
bool isEmpty(String string) => string.length == 0;

main() {
  isEmpty(null);
}
```

- `String`을 받아야 하는 함수에 `null`을 넘겼다.
- 함수 안에서 `string.length`에 접근하는데, `null`에는 `length`가 없다.
- 그래서 **`NoSuchMethodError`** 가 난다. 컴파일러가 잡지 못하고 **사용자 기기에서** 발생하는 에러다.

### null을 없애는 게 답은 아니다

null은 **값이 없음(absence)** 을 표현하는 유용한 값이다. 언어에는 이런 상태를 표현할 수단이 필요하다.
문제는 null 자체가 아니라 **null인 값을 참조하는 것**이다.

## 3. 기본적으로 모든 변수는 non-nullable

```dart
String nico = 'nico';
nico = null; // ❌ String 변수에는 null을 넣을 수 없다
```

Dart에서 변수는 **기본적으로 null이 될 수 없다(non-nullable).**

## 4. `?`를 붙이면 nullable 변수가 된다

```dart
String? nico = 'nico';
nico = null; // ✅ String 또는 null
```

타입 뒤에 `?`를 붙이면 Dart는 이 변수가 **String일 수도, null일 수도 있다**고 인식한다.

## 5. nullable 변수는 사용하기 전에 null 체크를 해야 한다

nullable 변수에 그냥 접근하면 컴파일러가 막는다.

```dart
String? nico = 'nico';
nico = null;
nico.length; // ❌ 컴파일 에러
```

> The property 'length' can't be unconditionally accessed because the receiver can be 'null'. Try making the access conditional (using '?.') or adding a null check to the target ('!').
> — `unchecked_use_of_nullable_value`

### 방법 1: `if`로 null 체크

```dart
if (nico != null) {
  nico.isNotEmpty; // ✅ 이 블록 안에서는 null이 아님이 보장된다
}
```

컴파일러는 이 블록에 도달했을 때 `nico`가 **확실히 null이 아니라는 것**을 알기 때문에 더 이상 에러를 내지 않는다.
[[5. Dynamic Type]]에서 `is`로 타입을 확인하던 것과 같은 원리(type promotion)다.

### 방법 2: `?.` 단축 문법

```dart
nico?.isNotEmpty;
```

`nico`가 null이 아닐 때만 `isNotEmpty`에 접근한다. `if (nico != null)` 체크를 짧게 쓴 것이다.

> [!note] 보충
> 에러 메시지에 나오는 `!`(null assertion)는 강의에서 다루지 않는다. `nico!`는 "이 값은 null이 아니다"라고 개발자가 단언하는 문법이고, 실제로 null이면 런타임 에러가 난다.

## 6. 실무에서는

- Flutter에서 **API로 데이터를 가져올 때** `?`를 자주 보게 된다.
- 대부분의 경우에는 변수가 null이 될까 걱정하지 않아도 된다. 기본이 non-nullable이기 때문이다.

## 정리

- Dart의 변수는 **기본적으로 non-nullable**이다.
- null을 허용하려면 타입 뒤에 **`?`를 명시적으로** 붙인다. (`String?`)
- nullable 변수는 **`if (x != null)`** 또는 **`x?.`** 로 null 체크를 한 뒤에 사용한다.
- 덕분에 null 참조 에러를 런타임이 아닌 **컴파일 시점에** 잡을 수 있다.
