변수를 **값 없이 먼저 선언하고, 값은 나중에 넣을 수 있게 해 주는** `late` 수식어를 다루는 강의다.

## 1. `late`: 값 없이 먼저 선언하기

`late`는 `final`이나 `var` **앞에 붙이는 수식어(modifier)** 다.

```dart
void main() {
  late final String name;
  // do something, go to api
  name = 'nico';
}
```

- 변수를 **데이터 없이** 만들 수 있다.
- API 호출처럼 무언가를 한 뒤, 데이터가 도착하면 **나중에(late)** 값을 넣는다. 그래서 이름이 `late`다.

## 2. `late final`은 여전히 `final`이다

```dart
late final String name;
name = 'nico';
name = 'las'; // ❌ final이므로 두 번 할당할 수 없다
```

`late`는 할당 **시점**을 늦출 뿐이다. [[7. Final Variables]]의 "한 번만 할당" 규칙은 그대로 적용된다.

## 3. 값을 넣기 전에는 접근할 수 없다

```dart
late final String name;
print(name); // ❌ 컴파일 에러
```

> The late local variable 'name' is definitely unassigned at this point.
> — `definitely_unassigned_late_local_variable`

- Dart는 `name`이 `late` 변수이고, 아직 값이 **확실히 할당되지 않았다**는 것을 안다.
- 그래서 값을 넣기 전에 접근하는 실수를 막아 준다. 강의에서는 이것도 **Null Safety의 일부**라고 설명한다.
- `name = 'nico';`로 값을 넣은 뒤에야 `print(name)`을 쓸 수 있다.

> [!note] 보충
> 위 에러는 컴파일러가 "아직 할당되지 않았다"고 **확실히 판단할 수 있을 때** 나는 컴파일 에러다. 컴파일러가 판단할 수 없는 경우에 할당 전에 접근하면, 실행 중에 `LateInitializationError`가 난다.

## 4. 언제 쓰는가

- 대부분의 경우에는 값을 미리 알기 때문에 `final name = 'nico';`처럼 바로 넣으면 된다.
- 값을 **미리 알 수 없을 때**, 특히 **API에서 받아 오는 데이터**를 담을 때 `late`를 쓴다.
- Flutter에서 자주 보게 되는 패턴은 다음과 같다.
  1. `late` 변수를 가진 무언가를 만든다.
  2. API를 호출한다.
  3. 응답이 오면 `late` 변수에 데이터를 넣는다.

## 정리

- `late`는 변수를 **값 없이 먼저 선언**하고 나중에 할당할 수 있게 해 준다.
- `late final`이면 할당은 여전히 **한 번만** 할 수 있다.
- 값을 넣기 전에 접근하면 Dart가 막아 준다.
- API 응답처럼 **나중에 도착하는 데이터**를 다룰 때 유용하다.
