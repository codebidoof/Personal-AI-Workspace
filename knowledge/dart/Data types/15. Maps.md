**key-value** 자료구조인 Map을 다루는 강의다. JS/TS의 object, Python의 dictionary와 비슷하다.

## 1. Map 만들기

중괄호 `{}` 안에 `key: value`를 나열한다.

```dart
var player = {
  'name': 'nico',
  'xp': 19.99,
  'superpower': false,
};
// 추론된 타입: Map<String, Object>
```

- key는 모두 `String`이므로 key 타입은 `String`이 된다.
- value는 `String`, `double`, `bool`이 섞여 있으므로 value 타입은 `Object`가 된다.
- value를 모두 문자열로 바꾸면 타입은 `Map<String, String>`으로 추론된다.

### `Object`란

Dart에서는 모든 것이 `Object`에서 나오므로([[11. Basic Data Types]]), `Object`는 **어떤 타입이든** 될 수 있다. 강의에서는 TypeScript의 `any`와 비슷하다고 설명한다.

> [!note] 보충
> 정확히는 Dart에서 TS의 `any`에 더 가까운 것은 [[5. Dynamic Type]]의 `dynamic`이다. `Object` 타입 변수에는 무엇이든 담을 수 있지만, 그 값의 메서드를 쓰려면 `dynamic`과 마찬가지로 `is`로 타입을 확인해야 한다. 반면 `dynamic`은 확인 없이도 아무 메서드나 호출할 수 있다(**틀리면 런타임 에러**).

## 2. 타입을 명시해서 만들기

```dart
Map<int, bool> player = {
  1: true,
  2: false,
  3: true,
};
```

`Map<key 타입, value 타입>`으로 적으면, 그 타입만 key와 value로 쓸 수 있다.

key와 value에는 어떤 타입이든 쓸 수 있다. 예를 들어 List를 key로 쓸 수도 있다.

```dart
Map<List<int>, bool> player = {
  [1, 2, 3, 5]: true,
};
```

## 3. Map의 프로퍼티와 메서드

Map도 클래스이므로 기능이 많다.

| 기능 | 설명 |
|---|---|
| `entries` | 모든 key-value 쌍 |
| `keys` / `values` | 모든 key / 모든 value |
| `isNotEmpty` | 비어 있지 않은지 확인 |
| `addAll()`, `addEntries()` | 여러 항목 추가 |
| `containsKey()`, `containsValue()` | 특정 key / value가 있는지 확인 |
| `putIfAbsent()` | key가 없을 때만 추가 |
| `remove()` | key 삭제 |
| `update()` | key의 값 수정 |

## 4. List와 Map 조합하기

[[12. Lists]]와 Map을 조합하면 복잡한 구조도 만들 수 있다.

```dart
List<Map<String, Object>> players = [
  {'name': 'nico', 'xp': 199993.999},
  {'name': 'nico', 'xp': 199993.999},
];
```

## 5. 구조화된 데이터에는 Map 대신 클래스

API에서 오는 player, movie, photo처럼 **정해진 형태가 있는 데이터**를 JS/TS의 object나 Python의 dictionary처럼 Map으로 만드는 것은 **권장하지 않는다.**
이런 경우에는 **클래스**를 쓰는 것이 좋다. Dart의 클래스는 강력하고, 편리한 문법과 단축 문법이 많다. 클래스는 뒤에서 다룬다.

## 정리

- Map은 `{key: value}`로 만드는 key-value 자료구조다. 타입은 `Map<K, V>`로 표시된다.
- `var`로 만들면 컴파일러가 key와 value 타입을 추론한다. 섞여 있으면 `Object`가 된다.
- `keys`, `values`, `containsKey`, `remove` 등 기능이 많다.
- 형태가 정해진 데이터는 Map보다 **클래스**로 표현하는 것이 좋다.
