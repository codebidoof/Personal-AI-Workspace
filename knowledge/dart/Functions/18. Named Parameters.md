Flutter에서 아주 많이 쓰는 **named parameters**를 다루는 강의다. 파라미터를 이름으로 전달하는 방법과, Null Safety 때문에 필요한 **기본값**과 **`required`** 를 설명한다.

## 1. positional parameters의 문제

```dart
String sayHello(String name, int age, String country) {
  return "Hello $name, you are $age, and you come from $country";
}

void main() {
  print(sayHello('nico', 19, 'cuba'));
}
```

- 모든 인자를 **정해진 순서대로** 보내야 한다. 하나라도 빠지면 에러가 난다.
- 호출하는 쪽에서 순서를 **잊어버리기 쉽다.**
- 코드를 읽는 사람도 `19`가 무엇을 뜻하는지 알기 어렵다.

> `age`를 `num`이 아닌 `int`로 한 이유: `num`은 `double`도 허용하는데, 나이는 정수여야 하기 때문이다. ([[11. Basic Data Types]])

## 2. named parameters: 파라미터를 `{}`로 감싼다

```dart
String sayHello({String name, int age, String country}) { ... } // 아직 에러가 난다 (아래 3 참고)

sayHello(
  age: 19,
  country: 'cuba',
  name: 'nico',
);
```

- 함수 정의에서 파라미터 목록을 **중괄호 `{}`로 감싸면** named parameters가 된다.
- 호출할 때 `이름: 값`으로 전달하고, **순서는 상관없다.**
- 자동완성이 파라미터 이름을 알려 주고, 타입이 틀리면 에러로 잡아 준다.
- 이름 없이 순서대로만 전달하는 방식은 더 이상 쓸 수 없다.

## 3. Null Safety 문제

named parameters는 호출할 때 **생략할 수 있다.** 그래서 `sayHello()`처럼 아무것도 보내지 않으면 `name`, `age`, `country`가 null이 될 수 있고, Dart는 에러를 낸다. ([[6. Nullable Variables]])

에러 메시지가 알려 주는 해결 방법은 두 가지다.

### 방법 1: 기본값 지정

```dart
String sayHello({
  String name = 'anon',
  int age = 99,
  String country = 'wakanda',
}) {
  return "Hello $name, you are $age, and you come from $country";
}

sayHello(); // Hello anon, you are 99, and you come from wakanda
```

값을 보내지 않으면 기본값이 쓰이므로 null이 될 일이 없다.

### 방법 2: `required` 수식어

기본값을 둘 수 없고 **반드시 사용자에게 값을 받아야** 한다면 `required`를 붙인다.

```dart
String sayHello({
  required String name,
  required int age,
  required String country,
}) {
  return "Hello $name, you are $age, and you come from $country";
}

sayHello();                                         // ❌ 컴파일 에러
sayHello(name: 'nico', age: 12, country: 'cuba');   // ✅
```

`required` 파라미터를 빠뜨리면 Dart가 **컴파일하지 않는다.** 강의에서 특히 좋은 기능으로 강조한다.

## 정리

- positional parameters는 순서를 기억해야 하고 읽기 어렵다.
- 파라미터를 `{}`로 감싸면 **named parameters**가 되어, `이름: 값`으로 순서와 상관없이 전달할 수 있다.
- named parameters는 생략할 수 있으므로 null이 될 수 있다. 해결 방법은 두 가지다.
  - **기본값**을 지정한다.
  - **`required`** 로 반드시 받게 한다.
