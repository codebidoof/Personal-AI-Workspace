지금까지 배운 **파라미터**를 복습하는 강의다. positional parameters와 named parameters를 비교하고, 언제 무엇을 쓸지 기준을 제시한다.

## 1. positional parameters

```dart
String sayHello(String name, String country, int age) { ... }

sayHello();                  // ❌ 세 개 모두 필수라서 컴파일되지 않는다
sayHello('nico', 'cuba', 12); // ✅
```

- **위치(순서)** 가 중요한 파라미터다. 정의된 파라미터는 모두 **필수**다.
- 문제는 **각 위치가 무엇인지 기억해야** 한다는 것이다.
  - 호출하는 줄만 봐서는 이해할 수 없고, 함수 정의를 **함께 봐야** 한다.
  - 함수가 다른 파일에 있으면 그 파일까지 열어서 첫 번째, 두 번째, 세 번째 파라미터가 무엇인지 확인해야 한다.
- 강의에서는 『Clean Code』도 이런 방식을 줄이라고 권한다고 소개한다.

### 강사의 기준

positional parameters는 **2개까지는 괜찮고, 최대 3개**다. 3개부터는 복잡해지므로 named parameters를 쓴다.

## 2. named parameters → [[18. Named Parameters]]

```dart
String sayHello({String name, String country, int age}) { ... } // 아직 에러가 난다 (아래 Null Safety 문제 참고)

sayHello(
  age: 12,
  name: 'nico',
  country: 'cuba',
);
```

- 파라미터 목록을 `{}`로 감싸면 된다. 마지막에 쉼표를 붙이면 포맷도 깔끔해진다.
- 호출하는 줄만 봐도 각 값이 무엇인지 알 수 있다. 자동완성도 되고 **순서도 상관없다.**

### Null Safety 문제와 해결책

named parameters는 생략할 수 있으므로 null이 될 수 있다. 그대로 두면 런타임에 null 에러가 날 수 있으므로, Dart가 미리 막는다.

| 방법         | 코드                     | 특징                                 |
| ---------- | ---------------------- | ---------------------------------- |
| `required` | `required String name` | 빠뜨리면 **컴파일되지 않는다.** 강사가 가장 선호하는 방식 |
| 기본값        | `String name = 'anon'` | 아무것도 보내지 않아도 기본값으로 동작한다            |

### 무엇을 쓸지는 함수에 따라 다르다

- 기본값이 있어도 되는 함수는 **기본값**을 쓴다.
- 데이터가 없으면 동작할 수 없는 함수는 **`required`** 를 쓴다. 예를 들어 **로그인** 함수의 email과 password에 기본값을 두면 안 된다.

## 정리

- positional parameters는 순서를 기억해야 하고, 호출부만 봐서는 읽기 어렵다. **2~3개까지만** 쓴다.
- 그 이상이면 `{}`로 감싼 **named parameters**를 쓴다.
- named parameters의 null 문제는 **`required`** 또는 **기본값**으로 해결한다. 값이 꼭 필요한 함수(예: 로그인)에는 `required`를 쓴다.
