함수에서 배운 **named parameters**를 **생성자**에도 적용하는 강의다. Flutter에서 아주 많이 쓰는 패턴이다.

## 1. 문제: positional 생성자는 금방 복잡해진다

[[24. Constructors]]의 생성자는 **positional** 방식이었다. 프로퍼티가 늘어나면 읽기 어려워진다.

```dart
class Player {
  final String name;
  int xp;
  String team;
  int age;

  Player(this.name, this.xp, this.team, this.age);
}

void main() {
  var player = Player("nico", 1500, 'red', 12);
  var player2 = Player("lynn", 2500, 'blue', 12);
}
```

- 순서를 **기억해야** 한다.
- 호출하는 코드만 봐서는 `1500`, `'red'`, `12`가 각각 무엇인지 알 수 없다.
- [[19. Recap (Parameters)|함수의 positional parameters]]와 똑같은 문제다.

## 2. 해결: `{}`로 감싸고 `required`를 붙인다

함수에서 했던 것과 똑같이, 생성자 파라미터를 **`{}`로 감싼다.** ([[18. Named Parameters]])

```dart
class Player {
  final String name;
  int xp;
  String team;
  int age;

  Player({
    required this.name,
    required this.xp,
    required this.team,
    required this.age,
  });
}

void main() {
  var player = Player(
    name: "nico",
    xp: 1200,
    team: 'blue',
    age: 21,
  );
}
```

- `{}`로 감싸기만 하면 `name`이 null일 수 있다는 에러가 난다. 생략할 수 있기 때문이다.
- 기본값을 줄 수도 있지만, 여기서는 **`required`** 를 붙여 반드시 받게 한다.
- `name`을 빠뜨리면 `The named parameter 'name' is required` 에러가 난다.
- 호출할 때 `key: value`처럼 쓰므로 **순서를 기억할 필요가 없고**, 코드만 봐도 의미를 알 수 있다.

## 정리

- 프로퍼티가 많은 클래스는 positional 생성자로 만들면 읽기 어렵다.
- 생성자 파라미터를 `{}`로 감싸고 `required this.프로퍼티`로 쓰면 **named 생성자 파라미터**가 된다.
- 함수에서 배운 named parameters, `required`, 기본값이 생성자에도 그대로 적용된다.
