인스턴스를 만들 때 값을 넘길 수 있게 해 주는 **생성자(constructor)** 를 다루는 강의다. 긴 방식으로 먼저 작성한 뒤, Dart의 짧은 문법으로 줄인다.

## 1. 문제: 모든 Player가 같은 값을 가진다

[[23. Your First Dart Class]]의 `Player`는 name과 xp가 고정되어 있었다. 인스턴스를 만들 때 이 값들을 인자로 넘기고 싶다.

## 2. 긴 방식: 생성자 안에서 직접 할당

생성자는 **클래스와 같은 이름**의 메서드다.

```dart
class Player {
  late final String name;
  late int xp;

  Player(String name, int xp) {
    this.name = name;
    this.xp = xp;
  }

  void sayHello() {
    print("Hi my name is $name");
  }
}
```

- 프로퍼티를 선언만 하고 값을 넣지 않으면 에러가 난다.
- 그래서 **`late`** 를 붙여 "값은 나중에 생성자에서 넣는다"고 알려 준다. ([[8. Late Variables]]) 강의에서는 `late`가 클래스에서 특히 유용하다고 설명한다.
- 파라미터와 프로퍼티의 이름이 같으므로, 프로퍼티를 가리키려면 `this.name`을 쓴다. ([[23. Your First Dart Class]]의 shadowing)

```dart
void main() {
  var player = Player("nico", 1500);
  player.sayHello(); // Hi my name is nico

  var player2 = Player("lynn", 2500);
  player2.sayHello(); // Hi my name is lynn
}
```

## 3. 짧은 방식: `this.프로퍼티`를 파라미터로

긴 방식은 반복이 많다. 프로퍼티에 이미 타입을 적었는데 파라미터에 또 적고, 받은 값을 다시 할당한다.

```dart
class Player {
  final String name;
  int xp;

  Player(this.name, this.xp);

  void sayHello() {
    print("Hi my name is $name");
  }
}
```

- **첫 번째 인자는 `this.name`에, 두 번째 인자는 `this.xp`에** 들어간다. 위치(순서)로 연결된다.
- 타입은 프로퍼티 선언에서 이미 알고 있으므로 다시 적지 않는다.
- `late`도 필요 없다. 생성자에서 바로 값이 들어가기 때문이다.
- 여러 줄이던 생성자가 **한 줄**이 된다. 실행 결과도 같다.

## 정리

- 생성자는 **클래스 이름과 같은 이름**의 메서드다.
- 긴 방식: `late` 프로퍼티와 생성자 본문의 `this.x = x;`로 할당한다.
- 짧은 방식: **`Player(this.name, this.xp);`** 처럼 쓰면 인자가 순서대로 프로퍼티에 들어간다. 타입도 `late`도 필요 없다.
