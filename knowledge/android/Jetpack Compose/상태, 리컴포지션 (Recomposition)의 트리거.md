리컴포지션은 **상태가 바뀔때마다 실행**된다. 그렇다면 상태(state)란 무엇일까?

컴퓨터 프로그래밍에서 상태는 "시간이 지남에 따라 변할 수 있는 값"** 을 말합니다. 안드로이드 앱에서 예를 들자면 다음과 같은 것들이 모두 **'상태'**입니다.

- 입력창(TextField)에 타이핑 중인 **글자**
- 뉴스 앱에서 서버로부터 받아온 **기사 목록**
- **체크박스가 체크되었는지** 여부 (True/False)

이제 일반 변수와 컴포즈에서 사용하는 상태 정의의 차이를 알아보겠습니다.

1. 일반 변수

```kotlin
@Composable
fun BadCounter() {
    var count = 0 // 일반적인 코틀린 변수

    Column {
        Text(text = "클릭 횟수: $count")
        Button(onClick = { count++ }) { // 클릭하면 숫자를 올림
            Text("더하기")
        }
    }
}
```

2. 컴포즈의 상태 정의

```kotlin
@Composable
fun GoodCounter() {
    // 1. remember와 mutableStateOf를 함께 사용합니다.
    // by 키워드를 쓰면 .value를 생략하고 일반 변수처럼 쓸 수 있어 편리합니다.
    // by를 쓰지 않을 경우
    // var count = remember { mutableStateOf(0) }
    // count.value = 5 같은 방식으로 값을 수정하게 됩니다.
    var count by remember { mutableStateOf(0) }

    Column {
        Text(text = "클릭 횟수: $count")
        Button(onClick = { count++ }) { // 이제 숫자가 올라가면 화면이 다시 그려집니다!
            Text("더하기")
        }
    }
}
```

먼저 일반 변수를 보겠습니다. 결과는 버튼을 아무리 눌러도 화면의 숫자는 0에서 변하지 않습니다.

이유:
- 상태가 아닌 일반 변수는 컴포즈가 관찰하고 있지 않아 값이 변경된 사실을 모릅니다.
- 만약 컴포즈가 관찰하더라도, `GoodCounter` 의 리컴포지션이 발생하면 `var count = 0` 줄이 다시 실행되면서 **값이 다시 0으로 초기화됩니다.** (**함수 자체를 다시 실행**합니다)

 줄이 다시 실행되면서 값이 다시 0으로 초기화됩니다. (함수 자체를 다시 실행합니다)

이러한 문제를 해결하기 위해 컴포즈가 변수의 변화를 눈치채게 하려면 특수한 상자에 담아야 합니다. 그것이 바로  `MutableState` 입니다.

- `mutableStateOf(value)` : 이 함수는 컴포즈가 지켜볼 수 있는 '특별한 상자'를 만듭니다. (`value`는 타입에 제한이 있지 않습니다.)
- 이 상자 안의 값이 바뀌면, 컴포즈는 "어? 이 값을 쓰는 UI들을 다시 그려야겠네!"라고 판단하고 리컴포지션을 시작합니다.
- 그러나 UI를 다시 그릴 경우 값이 `value`로 초기화 되기 때문에 `remember` 를 사용하는 것이다.
- `remember`: 리컴포지션이 일어날 때, **해당 변수의 값을 메모리에 저장**해두었다가 **함수가 다시 실행될 때 그 값을 복원**해준다.
