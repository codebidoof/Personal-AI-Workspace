## TOSS 이현우 개발자님의 에이전트 활용 방식

### 1. 프로젝트마다 별도의 세션을 만들지 않는 방식

- 각 프로젝트마다 AI 에이전트 세션을 따로 관리하는 방식 대신, **공통으로 사용할 AI 작업 환경을 별도로 구성**
    
- `Nunu`라는 프로젝트를 로컬에 따로 만들어 두고 활용
    
- 필요한 프로젝트와 `Nunu`의 파일/기능을 **심링크(Symbolic Link)** 방식으로 연결
    
    - 바로가기와 비슷한 개념
    - 실제 파일은 Nunu에 두고 **다른 프로젝트에서 해당 파일을 참조할 수 있음**
    
    ```markdown
    이런 식이 아닐까? 헤헷호애앵
    
    C:\dev\
    │
    ├── Nunu\
    │   └── skills\
    │       ├── rn-review\
    │       ├── device-test\
    │       └── sqa\
    │
    ├── Project-A\
    │   └── .claude\
    │       └── skills\
    │           ├── rn-review → Nunu\rn-review
    │           ├── device-test → Nunu\device-test
    │           └── sqa → Nunu\sqa
    │
    └── Project-B\
        └── .claude\
            └── skills\
                ├── rn-review → Nunu\rn-review
                ├── device-test → Nunu\device-test
                └── sqa → Nunu\sqa
    ```
    

### 2. Worktree 활용

- 프로젝트를 로컬의 원하는 위치에 Clone해 둔 뒤, **Git Worktree를 활용해 별도의 작업 공간을 만들어 작업**
- **하나의 Git 저장소에서 여러 브랜치를 각각 별도의 폴더로 checkout할 수 있어서, AI 에이전트들이 서로 다른 작업을 동시에 수행할 수 있다.**

### 3. 공통 Skill / Agent 활용

현재 토스에서 **Android Native와 React Native를 함께 개발**하고 있으며, React Native 프로젝트를 함께 진행하는 두 명에게 필요한 공통 작업을 별도로 구성해 활용

예:

- React Native 개발에 필요한 공통 Skill
- 두 사람이 공통으로 사용하는 Agent 설정
- 디바이스 검증 절차
- SQA(Software Quality Assurance) 절차

이러한 공통 요소를 별도로 관리하여 **반복적인 작업을 줄이고 개발 생산성을 높이는 방식**

### 4. Nunu 프로젝트

- 특정 기술 스택에 필요한 AI 작업 환경을 별도의 프로젝트로 구성
- 해당 프로젝트에서 필요한 Skill, 지식, 문서 등을 관리
- 실제 개발 프로젝트에서는 이를 연결해서 활용하는 방식으로 보임
- 여러 파일을 연결할 때 **상대 경로를 활용**하는 방식도 언급됨

## 5. Skill을 무작정 많이 만들지 않기

- Skill을 많이 만든다고 무조건 좋은 것은 아님
- **Skill 탐색 비용(Discovery Cost)**이 존재하기 때문
- 에이전트가 현재 작업에 어떤 Skill이 필요한지 판단하고 탐색해야 하므로 Skill이 지나치게 많아지면 오히려 비효율적일 수 있음
- 따라서 **실제로 필요한 Skill을 중심으로 적절한 개수만 유지하는 것이 중요**

> 필요한 Skill을 만들되, Skill을 무작정 양산하지 않는다.

## 6. 원문과 자료를 활용한 Knowledge Base 구축

- AI에게 특정 기술이나 작업에 대해 필요한 자료를 조사하게 하고, **원문을 기반으로 내용을 정리**
- 추가 자료 조사 결과도 함께 활용하여 AI가 사용할 수 있는 형태로 정리
- 이렇게 정리한 내용을 Agent나 Skill에서 활용할 수 있도록 구성

```
원문 자료
   ↓
추가 자료 조사
   ↓
AI를 통한 정리
   ↓
Knowledge Base
   ↓
Agent / Skill에서 활용
```

## 7. AI 개발 과정에서 발생한 실수도 Wiki에 축적

- AI 기능을 구현하면서 발생했던 **실수와 문제 해결 과정**을 Wiki에 기록
- 단순한 개인 메모가 아니라, AI가 이후 작업에서 참고할 수 있는 **지식 데이터**로 활용
- 과거의 실패 경험을 축적하여 같은 문제가 반복되는 것을 줄이는 방식

예:

```
AI 기능 구현
    ↓
문제 / 실수 발생
    ↓
원인 및 해결 방법 정리
    ↓
Wiki / Knowledge Base 저장
    ↓
다음 AI 작업에서 참고
```

## 8. AI 작업 환경에서도 설계가 중요한 이유

- AI에게 작업을 맡길 때도 **전체적인 구조를 먼저 설계하는 것이 중요**
- 설계 없이 데이터를 계속 추가하면 정보가 여러 곳에 흩어질 수 있음
- 정보를 적절한 위치와 구조로 배치해 두면 필요한 부분만 수정할 수 있음
- 결과적으로 **AI가 필요한 정보를 더 효율적으로 찾고 활용할 수 있는 구조**를 만들 수 있음

### 핵심

> **AI에게 많은 정보를 주는 것보다, 필요한 정보를 적절한 위치에 배치하고 구조화하는 것이 중요하다.**

```
무작정 정보 추가
      ↓
정보가 여러 곳에 분산
      ↓
AI가 필요한 정보 탐색
      ↓
탐색 비용 증가

          VS

정보 구조 설계
      ↓
정보를 적절한 위치에 배치
      ↓
필요한 정보만 탐색
      ↓
변경 범위 및 탐색 비용 감소
```

## 핵심 정리

- **Nunu**: 여러 프로젝트에서 공통으로 사용할 AI 작업 환경을 별도로 구성
- **Symlink**: 공통 Skill이나 자료를 여러 프로젝트에서 공유
- **Worktree**: 하나의 Git 저장소를 여러 작업 공간으로 분리하여 활용
- **Skill**: 필요한 것만 만들고 지나치게 양산하지 않음
- **Knowledge Base**: 원문, 조사 자료, 개발 중 발생한 실수 등을 축적
- **Wiki**: AI 작업에서 발생한 문제와 해결 방법을 지식으로 저장
- **설계**: AI가 사용할 정보도 적절한 위치와 구조로 배치하여 탐색 비용과 불필요한 변경을 줄이는 것이 중요
